# QuantX v0.1 Repository Architecture

## Status

Proposed implementation tree. This document is an architectural target, not a claim that these modules already exist.

## Design goals

- Modular monolith first.
- Event-driven, domain-centered core.
- Ports and adapters for external systems.
- Plugins for optional capabilities.
- Indian-market/F&O-native domain model without hard-coding a broker.
- One domain/execution model across backtest, replay, sandbox, paper, and live contexts.
- Local-first deployment with seams for later distributed execution.

## Dependency direction

```text
apps → api/application → domain/kernel
plugins → ports/domain contracts
market/research → domain/ports
adapters → ports
kernel → no infrastructure dependencies
```

The kernel must not import broker SDKs, UI frameworks, AI SDKs, or database drivers.

## v0.1 implementation subset

The first implementation should not create every directory above. The minimum viable subset is:

```text
kernel
 domain
 application/trading
 application/reconciliation
 ports
 market/india
 research/metrics
 api/rest
 api/websocket
 apps/cli
 plugins/brokers/paper
 plugins/strategies/examples
 tests/unit
 tests/contract
 tests/integration
```

Everything else can be introduced behind the same contracts as later milestones require.
