# QuantX v0.1 Acceptance Criteria

**Release status:** ACCEPTANCE COMPLETE for the declared programmatic local-first scope (ADR-008) — the release gate is closed (see RELEASE-01). This is local-integration acceptance only: not production-broker certification, not a CLI, no real-broker end-to-end execution.

**Audit baseline:** `main` at `6f771b5044d7c971b5da2301901534a5156df361` (PR #164 merge), revalidated locally with the locked environment with and without the Dhan extra. See `docs/roadmap/v0.1-local-host-integration-readiness.md` for the current implementation sequence.

This document is the normative v0.1 release checklist referenced by `docs/implementation/v0.1-build-order.md`. Statuses below are anchored to the revalidation at the stated baseline, which resolved the previously open TYPE-01, LIFE-01, FORMAT-01, and HOST-01 items with exact evidence. Update them when new local evidence changes a criterion. A passing unit test or a composed class does not by itself prove that a complete product surface is operable.

## Status vocabulary

- **PASS** — implementation and relevant test/validation evidence were found at the audit baseline.
- **PARTIAL** — the underlying capability exists, but an end-to-end composition or supported-environment gate remains unproven or incomplete.
- **GAP** — a required product capability or proof was not found.
- **NOT IN SCOPE** — explicitly excluded from the v0.1 local-first release; it must not be implied by release language.

## Release decision rule

The release gate remains **OPEN** until:

1. the local setup and documented supported product surface are deterministic from a clean checkout;
2. the required test, lint, formatting, and type-check criteria pass in the declared environment (or any exception is narrowly documented and explicitly accepted by the release owner);
3. the host lifecycle composition, including recovery-before-readiness, failure behavior, shutdown, and restart, is covered by offline integration tests;
4. all remaining PARTIAL/GAP items are closed or have an explicit, justified scope decision;
5. the exact candidate SHA, local commands, test totals, skips, warnings, and known limitations are recorded.

Passing this checklist establishes only the declared v0.1 scope. It does **not** imply real-broker end-to-end validation or production LIVE trading certification.
